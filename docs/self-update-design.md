# 软件内升级接入设计

用户已同意研究并接入下载后升级，目标设备为 fnOS 1.2.1。修复版本 0.1.14；旧版命令行安装方案已被设备证据否定，新接口仍需实机完整验收。

## 已确认的现状

- `fnmusic/updates.py` 负责公开 Releases 检查、架构匹配、SHA256 校验和安装包保存，目前没有安装入口。
- 管理 API 已通过飞牛管理员网关和请求来源校验；新增升级操作应沿用相同校验。
- `cmd/upgrade_init` 调用 `scripts.fpk_lifecycle` 的 `upgrade-init`，会停止扩展管理、代理和音源服务。
- 管理服务使用 `KillMode=control-group`。仅创建 asyncio 任务、普通子进程或脱离会话不足以证明升级进程能在服务停止后继续运行。
- fnOS CLI 文档区分本地 FPK 任务和商店云端更新。不能据此直接认定设备原生 `appcenter-cli install-fpk` 支持升级已经安装的应用。

## 接入约束

1. 保留现有“仅下载”入口，新增明确的“下载并升级”操作；普通检查更新和下载不会开始安装。
2. 升级前重新校验完整安装包、应用标识 `fnmusic-lx-first`、目标版本和设备架构，不接受页面传入任意安装路径、命令或应用名。
3. 自定义目录可能可被其他 NAS 用户写入。交给安装器前，需要从已校验文件句柄复制到应用私有目录，重新核对摘要，并使用该私有副本执行升级。
4. 原生升级命令必须先在目标设备验证能力和权限。优先使用应用中心支持的升级流程，保留当前数据卷、设置、音源和音乐目录；不以先卸载后安装代替升级。
5. 安装工作由独立 systemd 单元接管；其工作目录和运行脚本不能依赖升级时会被替换的应用安装目录。
6. 升级状态写入应用私有数据目录，跨管理服务重启保留。网页重连后读取目标版本和真实服务版本；不能仅因命令返回零就报告升级成功。
7. 失败必须记录可诊断的状态，页面提供已有手动升级入口，不声称支持未经验证的自动回滚。

## 当前需要的设备证据

在 NAS SSH 终端只读执行：

```bash
command -v appcenter-cli
appcenter-cli --help
```

根据实际列出的命令继续读取对应子命令帮助，确认覆盖升级能力、状态查询以及权限要求。如果设备没有合适的本机命令，再选择经管理员授权的应用中心 API 方案。此阶段不运行安装、卸载、停止或重启命令。

## 验证要求

- 自动升级必须由管理员明确触发，普通下载不安装；校验失败不执行升级。
- 错误应用、架构或非更新版本被拒绝；共享目录文件替换不能影响私有安装副本。
- 重复点击不会启动并发升级；下载失败、提交任务失败和任务超时都有明确状态。
- 管理服务停止后独立任务仍继续；升级后保留设置和接管偏好，读取实际版本后才宣告成功。
- 在目标 fnOS 1.2.1 验证完整覆盖升级。模拟测试只能证明任务编排逻辑，不能替代该验收。

## 2026-11-06 设备帮助证据与原实现

用户在 fnOS 1.2.1 root 终端确认 appcenter-cli 0.0.1，install-fpk/ install / install-local 的 --volume 帮助均注明 ignored during upgrades，当时据此推断 CLI 可覆盖升级，但未完成实机验证；后续结果已否定该推断。原实现采用固定 appcenter-cli install-fpk 私有包路径；通过独立 systemd 单元运行私有 Bash 脚本，禁止把系统权限不足误判为命令不存在。新增入口保留仅下载选项，真实安装验收待在 NAS 完成。

## 后续实机结果及0.1.14修正

上述帮助文字不能证明 install-fpk 支持覆盖升级。用户两次重放实际安装包均返回0和已安装提示，磁盘及运行版本仍为0.1.12，故原路径被否定。页面停在verifying来自误把退出码0当作升级完成。

用户确认本地Unix Socket `/var/run/com.trim.app.center.sock` 的升级前检查接口返回10030参数校验错误。修复采用独立Python标准库worker调用守护进程的暂存、升级前检查、升级提交和状态轮询接口，校验业务code而不是进程退出码。worker连同一份私有Python运行环境提前复制，避免旧安装目录被替换时丢失解释器。

保留旧应用所在的安装卷和数据卷，仅提交update/task，完全不走卸载重装。任务返回成功后检查磁盘版本，再等待新管理服务实际版本；不可观测的提交结果保持unknown，不重试变更。字段及接口事实的参考和验收记录见 superpowers/plans/2026-11-06-daemon-upgrade-fix.md。
