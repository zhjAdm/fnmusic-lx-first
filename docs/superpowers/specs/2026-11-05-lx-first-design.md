# 飞牛音乐在线扩展设计

用户已确认优先使用 LX 版聆澜音源，保留官方 App。

## 边界

新建 Python 3.11+ 模块化代理，参考 javycoder/fnos_music_ext 的公开协议；LX 搜索、榜单、歌单及脚本运行使用独立 lxserver v2.1.2 服务。只接入用户提供的 LX 脚本，不分发付费脚本。运行数据与脚本排除 Git。

代理监听独立 Unix Socket。单独的显式接管命令将官方入口切至代理；启动开发服务不接管。官方程序、nginx 配置和数据库均不修改。官方业务写入只走当前用户的官方 API。认证失败或身份缺失时拒绝扩展操作。

## 播放

默认 direct 模式：解析在线 HTTPS 链接并做 NAS 端轻量检查，支持直连时返回 302；不能直接使用时尝试 NAS 流式代理；在线失败再用官方 API 搜索并严格匹配标题、歌手、版本时长后播放本地条目。普通播放不落盘音频，NAS 中转仅保留有界内存缓冲。

302 后的手机网络错误不能由 NAS 可靠感知。不得宣称能无缝自动回退；提供显式 proxy 模式用于不支持直连的客户端。流式响应开始后也不能将两份不同音频拼接；中途断流保留错误，不偷换资源。断点请求只允许对同一资源续传。

## 喜欢、下载与入库

喜欢即记录当前用户意图并创建持久化任务。任务按用户和曲目去重；同一曲目的实体下载通过锁共享。最高质量按脚本声明能力从高到低尝试，不伪造无损。下载到临时文件，检查完整长度与 ffprobe 音轨、时长，再写标签并原子发布。仅喜欢动作触发，歌单浏览、推荐和普通播放不下载。

保存位置必须属于官方曲库扫描目录。通过官方扫描 API 请求扫描，查询官方搜索结果并按 audioSpec.path 校验入库文件路径。只有确认该文件的官方 GUID 后才收藏并加入当前用户的“默认歌单”；歌单不存在时通过官方接口创建。失败保留状态、有限退避重试。用户凭证仅在内存，重启后等待该用户重新访问恢复任务，不把 Cookie 写进任务库。取消喜欢取消待绑定意图，不删除已下载文件；已加入默认歌单的歌曲保留。

## 歌单与推荐

配置平台公共歌单及榜单，映射为虚拟官方歌单。热门推荐取榜单候选；喜欢推荐从已喜欢歌手搜索候选，过滤已喜欢曲目。按用户隔离，结果短期缓存；不引入大模型或平台账号专属日推。

## 验证

使用真实 SQLite、临时音频、HTTP MockTransport 验证认证、多用户、无落盘播放、Range、质量降档、持久任务恢复、仅入库后加歌单和错误传播。付费源实际取链及官方 App UI/协议验收需要 NAS 环境，作为独立部署验收列出，不用模拟测试代替。
